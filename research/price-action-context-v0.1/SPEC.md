## 1. 定义与来源边界

文章的核心顺序：

```
市场结构/环境 ─→ 关键价格位置 ─→ K线行为确认 ─→ 入场成本与风险收益
  (方向/禁做)      (为什么在这里)       (什么时候动)       (是否值得)
```

计算引擎贯彻“先结构、后位置、再形态、最后价格计划”。任何一个阶段不成立，不能仅凭漂亮 K 线给出可执行研究计划。

**三种信息等级必须分开**：

- **[原文 O]** 作者明确叙述的方向、相对大小、位置、交易规则；这并不意味着已经独立实证。
- **[实现 I]** 为让含糊词句可计算而做的**可替换假设**（阈值、识别算法、定价精度）。并非作者给出的精确数值；改变这些参数会改变结果。
- **[外部 X]** 交易所限制、数据来源、复权、一致性/未来函数约束、手续费与滑点、账户约束等；在文章中没有定义，不能冒充作者的策略。

## 2. 研究输入合同（封闭输入，禁止未来信息）

每根 K 线 `Bar(date, open, high, low, close)`，ISO 格式交易日期和**已完结** K 线，连续价格尺度一致。OHLC 均正，且 `low <= open/close <= high`。

1. 可读取完整日期序列；信号 K 线为最后一根，**以前的已完结 K 线**才可用于确认摆动点、计算关键位和趋势（防止右侧确认带来的未来数据泄漏）。[X]
2. 优先从封闭历史求出已确认局部高/低点；如使用日线/4 小时级别、人工/第三方确认的水平线或区间边界，外部输入每个 `Level` 须含 `price, kind, source, as_of`，`as_of <= signal.date`。未来标注一律 UNKNOWN。[O + X]
3. 信号时点、复权口径和后续可执行实际价格须匹配，禁止“后复权历史线 vs 未复权当日委托价”直接比较。[X]
4. 动画数值属于演示用例，不是实盘的历史价格样本；引擎不内置市场价格获取或证券交易接口。[X]

## 3. 市场结构识别

### 3.1 趋势与盘整 [O + I]

已确认摆动高点 `H1,H2` 和低点 `L1,L2`：

- `UP = (H2 > H1) and (L2 > L1)`；这是文章“高点抬高、低点抬高”的明确语义。[O]
- `DOWN = (H2 < H1) and (L2 < L1)`；相反结构。[O]
- `RANGE = 其余非单边组合`，**不能直接**推断所有区间位置无效：必须区分上下边界和中间。[O + I]
- `UNKNOWN = 不足两组已确认高低点`；不能强行给趋势标签。[I]

摆动点用左右各 `2` 根 K 线的严格局部极值确认；左右个数是实现参数，不是原文数字。[I] 由此形成的趋势判断具有右侧确认滞后，不具有“提前知道底部”的能力。

### 3.2 关键水平位置 [O + I]

- **支撑**：历史已确认低点、人工核验的关键水平/较大周期支撑；**阻力**：已确认高点/人工核验的水平阻力。
- 为处理价格轻微刺穿，定义容差 `ε = max(tick, 0.25 × ATR14)`。[I] 原文没有 ATR14 和 0.25；应作为可审计参数而不是“标准公式”。
- K 线区间触碰水平 `L`：`low − ε <= L <= high + ε`。[I] 存在位置联系**不等于**价格真正拒绝，仍要求对应信号。
- 若 `RANGE`，默认由最近已确认区间极值推断边界；也可显式提供经核验的 `(lower,upper)`。靠近边界才继续，箱体中央 `REJECT:RANGE_CENTER_NO_TRADE`。文章动画②明确强调此区别。[O + I]
- 原文提及“密集成交区”但没有给出成交分布算法，**本版本不伪造量价密集区判断**，需外部独立定义后才能采用。[O 未数值化]

### 3.3 上升趋势线和上升楔形 [O + I]

- **候选上升线**：连接两个已确认且上升的摆动低点，后续第 3 次碰触在容差内才认作可用上升支撑。[O + I] 代码实现用三个已确认的近共线摆动低点，并线性外推到信号日。
- **回踩次数**：第3个触点完成“已确立”，其后第4、第5个触点是头两次额外回踩。若近期能识别出第6个及以上连续近共线触点，研究引擎不再将该线视为高质量入场支撑。这里的“第6”是将作者“成立后第3～4次回踩谨慎”转换成保守禁入规则，并非作者给的连续 K 数/时长。[O + I]
- **上升楔形**：同一历史窗口可构成上方上升趋势线和下方上升趋势线，且 `0 < 上轨斜率 < 下轨斜率`、预测上轨高于下轨，表示两线收敛；信号上影线刺穿上轨并拒绝后，**做空触发还需跌破楔形下轨**。[O + I] 代码从近共线的 3 个摆动高点/3 个摆动低点生成候选；不能识别时不能宣称“楔形已确认”。
- 单纯价格刺破趋势线但仍未收盘或未满足确认，不将其误称“突破完成”。[O + X]

原文还提到头肩顶、三角形、双底、旗形等大形态，但没有逐一给出可复算的边界及触发定义；**本研究不能凭名字替作者杜撰其完整算法**。这些是后续扩展研究方向，当前自动检测仅覆盖作者提供了具体交易路径的上涨趋势线/楔形及关键水平位。

## 4. K线形态识别（仅在正确位置计入信号）

| 形态 | 可计算定义 | 文章与实现界线 |
|---|---|---|
| 看涨 Pin Bar | `下影/全幅 >= 2/3`，实体占比 `<= 1/3`，上影 `<= 15%` | 2/3 为 [O]；实体1/3、上影15%为 [I]；需在支撑 |
| 看跌 Pin Bar | `上影/全幅 >= 2/3`，实体占比 `<= 1/3`，下影 `<= 15%` | 同上；需在阻力/楔形上沿 |
| 看涨/看跌吞没 | 当前方向与前根相反；当前 `high >= prev.high and low <= prev.low`，当前实体大于前根 | “反向强势覆盖前K区间”属 [O]；是否必须**全高低价覆盖**属较严 [I] |
| 内包 Inside Bar | `high < mother.high and low > mother.low` | [O]；代码仅在上涨趋势回踩支撑允许正向触发 |
| Doji 十字星 | `abs(close-open)/(high-low) <= 10%` | `open≈close` 为 [O]；10%为 [I]；仅在上涨到强阻力/区间上边界做看跌确认 |

**形态与位置冲突**、只有形态没有关键位、横盘中央出现标准形态：过滤。形态检测本身只是形状分类，不推定多空胜率。[O]

## 5. 入场、止损、目标与收益风险

### 5.1 交易方向语义 [O]

- 上涨结构回踩支撑 + 看涨形态：**多头延续候选**；下跌末端触及强支撑 + 看涨 Pin/吞没：**反转候选**，但不保证趋势已经反转。
- 上涨接近阻力/上升楔形 + 看跌形态：**反转/退出候选**；下降结构在阻力附近看跌：**顺势延续候选**。
- 箱体中央不操作；箱体上边界的看跌 Doji、强拒绝或看跌吞没可形成研究候选。[O]
- `LONG/SHORT` 是文章的方向语义。**A股股票通常不能直接用普通账户做空**；本版本不会转换成可交易的卖空建议。[X]

### 5.2 两种入场方式 [O + I]

设确认 K 线高 `H`、低 `L`，最小跳动价位 `tick`：

| | LONG | SHORT |
|---|---|---|
| **方式A：破极值确认** | `entry = H + tick` | `entry = L − tick`；上升楔形须同时跌破下轨 `entry = min(L, wedge_lower) − tick` |
| **方式B：50%～61.8%回撤** | 等待回撤区 `[H−0.618(H−L), H−0.5(H−L)]`，默认按50%端设计划价 | 等待回抽区 `[L+0.5(H−L), L+0.618(H−L)]`，默认按50%端设计划价 |

破极值后增加一档 `tick`、把50%端作为默认进场价属于 [I]，不是作者给出的标准订单行为；实际仍需下一根及以后 K 线满足价格条件，不能在信号 K 线上回填成交。

**不得**把“50～61.8%一定会回来”视为事实；没有回踩就不成交，不倒推成交。

### 5.3 止损、目标及准入 [O + I]

- LONG 初始结构止损：`stop = L − tick`；SHORT 初始结构止损：`stop = H + tick`。[O: 在信号形态极值外侧；I: 精确一 tick]
- LONG 的目标：入场后**最近的上方有效阻力**；SHORT 的目标：入场后**最近的下方有效支撑**。若没有可证明的下一障碍位，返回 UNKNOWN，不胡编收益空间。[O + I]
- `风险 R = |entry − stop|`；`潜在收益 G = |target − entry|`（方向一致时）；`RR = G / R`。仅在 `R>0, G>0, RR>=2` 时输出 `PLAN`。否则 `REJECT`。[O: 最低目标1:2；I: 最近障碍取值约定]
- RR 是**毛**值，不包含手续费、冲击成本、滑点和跳空执行差异；净RR计算需要账户及市场输入。[X]
- 文章没有提供胜率，也没有单笔风险百分比或仓位算法。因此**不计算经验胜率、不擅自确定仓位**；任何账户层资金管理是独立新增模块，不属于原文。[X]

### 5.4 出场与持仓 [O + I]

1. **初始止损/目标**：触及结构止损或目标，研究回放记录理论退出。若同根 OHLC 同时触及止损、目标，标记 `AMBIGUOUS`，不假定有利顺序。[O + X]
2. **反向强吞没**：持仓后出现方向相反且明显的吞没，可选择在该信号 K 线收盘理论退出（`OPPOSITE_ENGULF_AT_CLOSE`）。[O: 作为提前退出风险提示；I: 出场精确至收盘]
3. **1R 保本保护**：浮盈达到1倍初始风险，可以选择把保护价移动至计划入场价；离线回放为避免同根路径臆断，**仅下一根**生效。[O: 可选保本；I: 次根生效]
4. **时间止损、加仓、交易佣金、部分止盈**：原文无可计算合同，不擅自添加。[X]
5. **结构先失效再入场**：等待回撤/突破期间若价格先触及结构止损，旧计划立刻 `CANCELLED:STRUCTURAL_INVALIDATION_BEFORE_ENTRY`，不能重新用失效信号入场。[O + I]
6. **缺口穿越入场价**：未知真实成交价时返回 `UNKNOWN:GAP_THROUGH_ENTRY`，而不是按理想价假成交。停牌/涨跌停/不可成交时真实执行需另行验证。[X]

## 6. 研究决策状态机

```
INPUT_SNAPSHOT
  ├─数据不足/日期乱序/未来水平位──── UNKNOWN
  └─历史合法
      ├─结构UNKNOWN──────────────── UNKNOWN
      ├─盘整中央─────────────────── REJECT
      └─结构明确 / 区间边界
          ├─没有匹配的支撑阻力────── REJECT
          ├─没有对应K线确认───────── REJECT
          └─结构+位置+信号一致
              ├─没有客观下一目标──── UNKNOWN
              ├─两种入场均不足2R──── REJECT
              └─至少一种入场满足2R── PLAN (PENDING_NOT_FILLED)
                      ├─未触发───── NOT_ENTERED
                      ├─同根路径不确定 AMBIGUOUS
                      ├─跳空执行未知 UNKNOWN
                      └─触发后───── OPEN / EXIT(STOP,TARGET,OPPOSITE_ENGULF)
```

`PLAN` 只意味着**研究价格方案可计算**；不表示已下单、真实可成交、满足账户/市场风控或具备真实交易许可。

## 7. 四段视频与公式对账

这四段是**人工绘制示例**，不证明价格行为策略胜率：

1. 视频①：同样看涨 Pin Bar，在支撑区、上升趋势线首次回踩、半空位置的后续路径不同。原文强调**位置决定语义**，并非“长影=买入”。
2. 视频②：横盘中间出现内包线/十字星反复假突破；上涨回踩支撑的内包线，或区间上边界的 Doji 才有上下文。体系不能简单“震荡全部否决”。
3. 视频③：上升楔形上沿长上影 + 下轨跌破后做空的示意：`entry=106, stop=109.5, target=95.5` → `R=3.5`，`G=10.5`，`RR=3:1`。
4. 视频④：同一看跌示例，
   - 方式A：`entry=103.5, stop=110.5, target=89.5` → `R=7`, `G=14`, `RR=2:1`；
   - 方式B：`entry=107, stop=110.5, target=89.5` → `R=3.5`, `G=17.5`, `RR=5:1`；
   - **但**方式B必须等价格真的回抽到该区，并且回抽前不能已触发结构失效；不能假设总是成交。

`test_engine.py` 使用构造的合规信号棒把上述 3 组数字复算，属于**数学回归测试**，不是历史行情还原或市场有效性检验。

## 8. 用法与输出

在仓库 `research/price_action_context_v1` 目录执行：

```bash
python3 -m unittest -v test_engine
```

最小使用方式：

```python
from engine import Bar, Level, Config, evaluate_latest, to_dict

bars = [...]                 # 已收盘、按 ISO 日期严格升序的同一价格尺度 OHLC
verified = [
    Level(price=10.0, kind="SUPPORT",
          source="VERIFIED_DAILY_LEVEL", as_of="2026-11-16"),
    Level(price=12.5, kind="RESISTANCE",
          source="VERIFIED_DAILY_LEVEL", as_of="2026-11-16"),
]
result = evaluate_latest(bars, Config(tick=0.01), supplied_levels=verified)
print(to_dict(result))
```

结构化结果包含 `status, reason, regime, location, pattern, side, plans[]`。每种计划单独给出：

`entry_mode, entry_price, retrace_band, trigger_price, stop_price, target_price, risk_per_share, reward_per_share, gross_rr, signal_date, execution, trade_authority=False`。

使用方必须留存 OHLC 冻结快照、交易日、价格尺度、配置哈希和来源；仅展示最终数字不构成可复现证明。

## 9. 验收边界及下一步

**当前可验证**：代码语法、K线形态、确认摆动点、结构分类、区间边界过滤、三点趋势线、视频算术、RR否决、日期防泄漏、保守 OHLC 回放、反向吞没退出和跳空未知。

**公开协作边界**：本目录只讨论“结构位置 / 形态确认 / 入场成本”的量化方法，不代表任何现有交易系统的正式规则。生产使用需要另行审计、验证和授权。
